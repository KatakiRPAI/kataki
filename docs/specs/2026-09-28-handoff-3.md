# Kataki RPAI — the third design handoff (1:1 build)

The handoff is in `docs/handoff/kataki-handoff/` (start at its `README.md`). The user, 2026-09-28:
"The handoff is the source of truth… we're making it a website and a local app. Do as the handoff
says, nuke the old design." Stack: "whatever choice is best."

## Decisions

- **The handoff wins** over every earlier design doc (`docs/design/`, `docs/kataki-design/`, the
  2026-09-19 UI spec). The old UI code goes as the new one lands; no "classic" mode.
- **One UI, two hosts.** The Python engine keeps owning the library and serves the HTTP API (the
  handoff's "main process owns the library over typed IPC" is the same shape: a typed client in
  `api.ts`). In Electron the router is `createMemoryRouter`; on the web it is
  `createBrowserRouter`. Same routes, same components. *Mismatch reported: DATA.md's "main process"
  is our engine process.*
- **New deps, as the handoff asks:** `react-router` (routing) and `intl-messageformat` (ICU strings).
  Nothing else.
- **The design system** is vendored as shipped: `app/src/ds/` holds `tokens.css`, `bundle.css`,
  `bundle.js` (sets `window.Kataki`, reads `window.React`) and `index.d.ts`; `app/src/ds/layout.css`
  is the handoff's `boards/app/app.css` (COMPONENT-GAPS §3). COMPONENT-GAPS §1–2 changes are made in
  `bundle.js` itself, each as it is needed, keeping English defaults.
- **Strings** live in `app/src/strings/en.json` (ICU), seeded from `strings.boards.en.json`;
  `t(key, values)` is the only way text reaches a component.
- **Art and fonts** are local (renders with no network): Baloo 2 is added to `ds/fonts/`; the
  sample art comes from `docs/design/assets/`.

## Slices (show-first: each one ends on screen and committed)

1. **Foundation + Home + playable Scene.** Deps, vendored DS, strings + `t()`, router with all 26
   paths (unbuilt ones render a plain "not built yet" page), Sky shell (Rail, TopBar, Sky), Home
   (C1–C3), the Scene core (P1: lines, composer, streaming, stop, Try again). Old UI deleted.
2. Stories (H1–H6) and New story (G1–G4).
3. Characters (D1–D5), profile (E1–E5), make/edit (F1–F7).
4. The rest of the Scene: takes/edit/hide, people, widgets, time, reading mode, first moment,
   narrator and plots (P2–P21), then Backstage (Q1–Q5).
5. Settings (K1–K18), with Models first.
6. World (I1–I8), You (J1–J3).
7. Opening, first run, system (A1–A3, B1–B6, N1–N3), palette and search (C4–C9), Feedback (L).
8. Errors (`errors.json` wired to every surface), keyboard (KEYBOARD.md), proofs R1–R5
   (1024 wide, Arabic RTL, 200% zoom, access, Day), the placeholder build check.
9. Website build: the engine serves `app/dist` with the browser router.
