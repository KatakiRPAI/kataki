## Context

Kataki RPAI is a greenfield, open-source AI roleplay **harness framework + desktop app**. No models are baked in: users connect local models, HuggingFace, or paid APIs and pick a model per *role* (RP text, utility/extraction, embeddings, image, music). Differentiators: (1) realism-first graph memory with per-character knowledge, forgetting, story-time decay and lie-challenging, in SQLite; (2) a cache-friendly token economy for small local models; (3) consistent scene images; (4) location/mood-adaptive music with slow crossfades; (5) a deep library (books/stories/chapters, folders, cross-story canon links).

`D:\OpenRolePlayAI` is empty (no git). Three parallel web-research passes (Sept 2026) found that **no existing RP platform ships per-character epistemic memory, story-time decay, or contradiction challenge** — SillyTavern/Risu/NovelAI rely on keyword lorebooks + lossy recursive summaries; Talemate is closest but spends many LLM calls per turn. That is the open ground.

The project is 6+ independent subsystems, so it is decomposed into milestones. **This plan fully specifies M0 + M1** (scaffold; chat + complete memory engine). M2–M5 are designed at architecture level and each gets its own spec → plan cycle when reached.

## Model selector & roles (reasoning vs standard models)

Every task the engine performs routes through a **role** (a model slot). The **Models page** is the selector: one row per role — provider dropdown → model dropdown (live from `/v1/models`) → **kind badge** (Reasoning / Standard, auto-detected, overridable) → params. An unset role shows "inherits from …". The chat header has a quick-switch for the `rp` model. Per-story overrides live in `stories.overrides.roles` (e.g. a horror story on a different RP model) — no extra table.

| Role | Tasks routed to it | Preferred kind | Inherits from |
|---|---|---|---|
| `rp` | character replies | Standard (latency, prose); Reasoning accepted | — |
| `narrator` | narrator-speaker replies, scene descriptions | Standard; Reasoning accepted | `rp` |
| `utility` | per-N-turn extraction, scene summaries, JSON tasks; temp fixed 0 | **Standard** (fast, cheap, grammar-friendly) | `rp` |
| `reasoning` | scene-close consolidation (who-knows-what attribution on the closing window), inspector actions "Re-extract with reasoning model" and "Resolve merge candidates", stale-run re-extraction; seam for the M2+ director/plot planner | **Reasoning** | `utility` |
| `embed` | embeddings | — (static local model by default) | none (FTS + graph fallback) |
| `image`, `music` | M3 / M4 | — | none |

Nothing on the per-turn hot path *requires* a reasoning model — the `reasoning` role only does off-path, accuracy-sensitive work, so the token economy holds. Both kinds work in every text role; the kind changes how the harness drives the model:

- **Kind detection.** "Test connection" sends one tiny probe and marks the model Reasoning if the stream carries `reasoning_content` deltas or an inline `<think>` block. Stored as `model_roles.detected_kind`; the user's `kind` override (`auto | reasoning | standard`) wins. No model-name heuristics.
- **Reasoning model in `rp` / `narrator`.** Thoughts are streamed to a separate SSE event (`thought`), shown as a collapsible block (toggle `show_thoughts`), stored only in `messages.gen.reasoning`, and **never** enter prompt history (kills the duplicate-reasoning-on-swipe bug and keeps the cached prefix stable). Inline tag pairs are configurable (`think_tags`, default `<think>`/`</think>`) and parsed across SSE chunk boundaries. Per-role params: `thinking: default | enabled | disabled` (sent as `chat_template_kwargs.enable_thinking` / `reasoning_effort`, passed through verbatim), `reasoning_effort`, and `think_budget_tokens`, which is **added to the response reserve** in the context budget (default +1500 for Reasoning kinds — matters on 8k contexts).
- **Reasoning model in `utility` / `reasoning` (JSON tasks).** Grammar-constrained decoding conflicts with think blocks on some backends, so the ladder for Reasoning kinds is: request thinking disabled + `json_schema` when the role is `utility`; for the `reasoning` role keep thinking on and use `json_object` → strip thoughts → parse first `{…}` → one retry with the error appended. Standard kinds use plain `json_schema`.
- **Standard model in the `reasoning` role** is allowed (it simply inherits or runs without thoughts); the UI shows a soft hint, never a block.
- **8 GB tip (built into the wizard's suggestions):** two different local models cannot co-reside in VRAM, so the zero-cost setup is one *hybrid-thinking* GGUF serving `rp`/`utility` with `thinking: disabled` and `reasoning` with `thinking: enabled` — same weights, same endpoint, different role params. Alternatives: point `reasoning` at an API / HF Inference model, or at a CPU-only llama-server. Because `thinking` is a per-role param rather than a per-model property, all three work with no special cases.

## Memory engine

**Two layers.** *World truth*: `memories` (kind `event | fact | claim`) linked to entities through `memory_entities` with roles `actor | target | witness | place | item | subject` — place and items are roles, so the character↔character↔place clique exists by construction (req. 2). *Per-character view*: `knowledge(knower, memory, source ∈ witnessed|told|overheard|rumor|inferred|innate, told_by, learned_story_time, fidelity, belief)`. Retrieval for a speaker **hard-filters through `knowledge`** and `story_time ≤ now`: an absent character cannot retrieve an event at any relevance (req. 3). Code, not the LLM, decides witnesses: `participants ∪ scene presence at that message`, or participants only when the event is `covert`. First-order theory of mind only.

**The generation unit is one speaker.** A single reply voicing several NPCs would put everyone's secrets in one prompt and small models leak them. So: the stable prefix holds only *public* descriptions of present characters (prefix cache survives speaker changes); the volatile tail holds only the **current speaker's** memories + `private` card text. Speaker choice is deterministic: UI pick → name mentioned in last user message → last speaker / round-robin. The **narrator** is a speaker with no episodic memory (scene state, public flags, pinned place facts). Classic "one GM card voices everyone" remains as a fallback mode labelled *leaky* in the UI. The **persona** is an ordinary entity: it gets `witnessed` rows and is the `told_by` of everything the user says (the entry path for lies); retrieval never runs for it, and a stop string `\n{persona}:` forbids voicing it. "Play WITH" = persona NULL (director mode).

**Nothing is mutated or deleted.** Every derived row carries `run_id`. A row is *live* if its run is `ok` and the run's `to_message_id` is on the active path (recursive CTE leaf → root, cached per leaf). Swipes/branches therefore never corrupt memory and switching branch is free. Contradicted truth is superseded by a newer live row (`supersedes_id`), flags/edges/knowledge/presence are append-only logs whose current value is the latest live row ≤ now. **Lag rule:** the leaf AI message is never extracted — a user reply is implicit acceptance, so ordinary swipes never touch memory. Editing a message marks the covering run `stale` and the inspector offers re-extract. Forgetting is a *render-time* effect over intact data.

**Story clock is owned by code.** `messages.story_time` = parent + per-turn tick (default 2 min) + `skip_minutes`. Skips come from a deterministic regex parser over user and AI text ("six years later", "next morning"), auto-applied with an undo chip, plus manual controls. Extraction only returns a bucket hint (`none|hours|days|weeks|months|years`) used to *suggest* a skip the regex missed. Power-law decay forgives errors (a 2× time error ≈ 0.35 activation units).

**Activation** per (knower, memory), story-minutes, zero LLM calls:

```
dt_j  = max(now − t_j, 10)
B     = min(0, ln Σ_j w_j · dt_j^(−d))        d = 0.5  → the user-facing "memory sharpness" slider (0.3–0.8)
        accesses: implicit encode at learned_story_time (w=1, sharp) + recall (w=0.5) + retold (w=1, sharp)
A     = B + 3.0·(imp/10) + 1.5·S + 1.0·G + F − 2.0·superseded + noise
S     = RRF(k=10) of FTS5-BM25 and vector ranks, normalised to [0,1]
G     = 1.0 shares an entity with seeds (mentioned entities + current place); 0.5 two-hop or present-unmentioned; else 0
F     = witnessed/innate 0 · told −0.5 · overheard −0.75 · inferred −1.0 · rumor −1.5
noise = clip(0.25·logit(hash01(knower,memory,scene)), ±0.75)   constant within a scene (cache-stable); 0 in tests
SHARP : A_detail ≥ −2.0  (B over sharp=1 accesses only) → inject `detail`
HAZY  : A_all    ≥ −4.0                                 → inject `gist` + "(hazy)" marker;  else not recalled
```

`detail` and `gist` are both written **once at extraction time** — no later call, no mutation. Reinforcement is capped by the database: `accesses` PK is `(knower, memory, scene, kind)` with `INSERT OR IGNORE` → one reinforcement per scene. **Detail ratchet:** recalling a gist keeps the gist accessible but never resurrects detail. **"Tries to remember"** (req. 5): when a HAZY memory is injected on two consecutive turns (the topic is being pressed), one deterministic roll per (knower, memory, scene): `hash01 < sigmoid(A_detail + 2.0)`; success renders `detail` with "(after straining to recall)" and logs a sharp access; failure keeps the gist for that scene.

Worked example — Mira witnessed "Tobin betrayed the guild at the docks", importance 9:

| Situation | B | A | Result |
|---|---|---|---|
| Next day, cued (S=0.9, G=1) | −3.64 | **+1.41** | SHARP |
| After "six years later", cued | −7.48 | **−2.43** | HAZY — gist only |
| Same, uncued (S=0.2, G=0) | −7.48 | −4.48 | not recalled |
| Six years, but retold yearly | −5.29 | **−0.24** | SHARP (rehearsal saves it) |
| Six years, gist recalled 30× yesterday in one scene | −4.29 (all) / −7.48 (detail) | +0.76 / −2.43 | retrievable, still HAZY; effortful recall p = 0.39 |

Importance — both 30 days old, same cue: importance 9 → −0.29 SHARP; importance 2 ("green apron") → −2.39 HAZY; importance 2 at six years → −4.53 gone even when cued. (Importance 10 vs 1 ≈ 220× lifespan.)

**Lies / contradictions — zero extra per-turn calls.** A false claim is semantically close to the memory it contradicts, so normal retrieval surfaces that memory with its tier, and a fixed system rule drives behaviour: conflicts with a SHARP memory → challenge; HAZY → doubt, may yield (and the effortful-recall roll may fire); nothing recalled → accept. Data model: narration (`asserted_by` NULL) is truth and may supersede; anything asserted by a character is `kind='claim'`, `is_true` NULL, never supersedes truth, and creates `told` knowledge for the hearers. At the next extraction run, a `contradictions[]` entry referencing a true memory sets the claim `is_true=0` and hearer `belief` by resolution: challenged 0.1 · doubted 0.5 · accepted 0.9. A gaslit character is a feature that falls out of the schema.

**Extraction.** Not per turn. Triggers: every N turns (default 5) · scene break · time skip · extract-before-evict · manual. One `json_schema`-constrained utility call. **Closed-set references:** the prompt carries a roster (`E12 Marta (character) aka innkeeper`, recently injected memories as `M31`) and the schema constrains every reference to an `enum` of roster handles plus pre-allocated `N1..N8` for new entities — small models cannot invent or misspell ids. Dedupe: normalised exact alias match of the same kind merges automatically; cosine ≥ 0.85 becomes an inspector "merge?" chip (bias to under-merge: duplicates are repairable, false merges are not); pronoun stoplist. **Idempotency:** run row created `pending` → LLM call → raw JSON saved on the run → validate + apply in ONE transaction; retry = delete the run row, `ON DELETE CASCADE` wipes every derived row. Per-item validation (bad items → `warnings`). Output ladder: `json_schema` → `json_object` → strip `<think>` and parse first `{…}` → one retry with the error appended → `failed`. Startup resets `running` → `pending`. **Invariant:** a message leaves the verbatim window only if an ok run covers it. Budget ≈ 1.2 utility calls per 5 turns.

**Per-turn retrieval (0 LLM calls).** Seeds = entities matched in the last 2 messages by a cached per-story alias regex (longest first) + current place → candidates = 1-hop ∪ 2-hop graph joins ∪ FTS top-30 ∪ vector top-30 → RRF → live + visibility + time filter → activation → tiers → effortful recall → greedy fill of the memory budget (detail → gist as it tightens) → log accesses. A memory whose source messages are still in the verbatim window is never injected.

**Tags & flags (req. 8).** `tags`/`taggings` = free tag words on any lib item, story, entity or memory, mirrored into `memories.tags_text` for FTS recall. `flags` = typed state with story-time validity (`alive`, `location`, `outfit`, `injured`, `holding`, stance…, optionally `private`) → the always-injected compact **world-state block**.

## Context & token economy

Layout strictly **stable → volatile**:

1. System rules + format + memory-tier rules (never changes)
2. Public character cards + persona + world primer + `pinned` memories (changes only on edit)
3. Scene-summaries block (append-only)
4. History window — slides in **big chunks** (drop oldest 25% at once) so the prefix stays byte-identical across many turns
5. Recent turns (never evict the last 4)
6. **Volatile tail, prepended to the final user message and never persisted:** world-state flags, speaker's private card, speaker's recalled memories with tier/belief markers, directives. (Trailing/mid-conversation system messages break Mistral and Gemma templates.) Consecutive same-role messages are merged; NPCs are `assistant` with a `Name:` prefix.

Defaults at 8k (same fractions scale): response 600 · rules 350 · cards+primer 1400 · summaries 900 · memory tail 900 · flags+directive 250 · history = remainder. Eviction order: memories detail→gist (lowest A first) then drop → oldest 25% of history (after extract-before-evict) → oldest 25% of summaries → example dialogue. Never evict rules, card core, last 4 messages. Token estimate = `len/3.6`, **self-calibrated per model** from `usage.prompt_tokens` (ratio stored in role params) + 8% margin — no tokenizer dependency. Every turn writes `context_log` → live token meter, resolved-prompt viewer, per-memory activation breakdown, and what was cut.

```sql
  INSERT INTO memories_fts(memories_fts,rowid,detail,gist,tags_text) VALUES('delete',old.id,old.detail,old.gist,old.tags_text); END;

  story_time INTEGER NOT NULL, sharp INTEGER NOT NULL, weight REAL NOT NULL, message_id INTEGER,
  PRIMARY KEY(knower_id,memory_id,scene_id,kind)) WITHOUT ROWID;          -- the PK IS the reinforcement cap

  entity_id INTEGER REFERENCES entities ON DELETE CASCADE, model TEXT NOT NULL, dim INTEGER NOT NULL, vec BLOB NOT NULL,
  CHECK((memory_id IS NULL)<>(entity_id IS NULL)));
CREATE UNIQUE INDEX ux_emb_m ON embeddings(memory_id,model) WHERE memory_id IS NOT NULL;
CREATE UNIQUE INDEX ux_emb_e ON embeddings(entity_id,model) WHERE entity_id IS NOT NULL;
CREATE TABLE summaries(id INTEGER PRIMARY KEY, story_id INTEGER NOT NULL REFERENCES stories ON DELETE CASCADE,
  scene_id INTEGER REFERENCES scenes ON DELETE CASCADE, to_message_id INTEGER, story_time INTEGER, text TEXT NOT NULL, tokens INTEGER, RUN);
CREATE TABLE extraction_runs(id INTEGER PRIMARY KEY, story_id INTEGER NOT NULL REFERENCES stories ON DELETE CASCADE,
  from_message_id INTEGER NOT NULL, to_message_id INTEGER NOT NULL, trigger TEXT NOT NULL, -- cadence|scene|skip|evict|manual
  status TEXT NOT NULL DEFAULT 'pending' CHECK(status IN('pending','running','ok','failed','cancelled')),
  stale INTEGER NOT NULL DEFAULT 0, attempts INTEGER NOT NULL DEFAULT 0, model TEXT, raw JSON, warnings JSON, error TEXT,
  started_at TEXT, finished_at TEXT, UNIQUE(story_id,from_message_id,to_message_id));
CREATE TABLE context_log(id INTEGER PRIMARY KEY, story_id INTEGER NOT NULL REFERENCES stories ON DELETE CASCADE,
  message_id INTEGER REFERENCES messages ON DELETE CASCADE, speaker_id INTEGER, budget INTEGER,
  sections JSON NOT NULL,   -- [{name,tokens,cap,evicted}]
  memories JSON NOT NULL,   -- [{memory_id,tier,A,B,S,G,imp,F,noise,effortful,tokens}]
  prompt TEXT,              -- pruned to last 20 per story
  est_tokens INTEGER, actual_tokens INTEGER, cached_tokens INTEGER, created_at TEXT DEFAULT CURRENT_TIMESTAMP);
```

A scene is live if its `start_message_id` is NULL or on the active path; `accesses` liveness follows its scene. `ponytail:` an access from a dead swipe inside a live scene still counts (bounded to one row per scene); filter on `message_id` if it ever matters.
