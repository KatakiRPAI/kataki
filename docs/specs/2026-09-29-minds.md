## 1. Decisions (owner, 2026-09-29)

1. **The research is the source of truth** for the app and the website. It supersedes these
   lines of the M0/M1 spec's "Deliberately NOT building" list: *mutating stored memories to fake
   distortion* (built instead as append-only per-character recollections; truth rows are still
   never touched), *reflection / "dream" cycles* (built as the Between job's deep pass, gated and
   inspectable), *higher-order theory of mind* (one second-order slot, premium only).
2. **Default realism** is enough to stand clearly apart from every competitor and feel new, and
   never so much that roleplay stalls. The rules that keep roleplay possible are in §6.
3. **Legal** (companion-app laws, payment processors, "operator" status) is the owner's job.
   Build as if green-lit. The only product rule kept from the research is the one that is also a
   UX rule: a sincere out-of-character question is answered out of character (§6).
4. **Two products, one engine, the same features.** The open-source desktop app (GitHub
   releases) and Kataki online (hosted, online models, pay-as-you-go credits at cost plus a small
   margin). A feature ships to both or to neither; they differ only in where models run and who
   pays (§4).
5. **Alpha and beta on both.** Desktop: release channels. Online: beta accounts. One feature-flag
   registry in the engine serves both (§5).

## 3. Target: the mind, in one page

Adopted from note 22 without change unless stated. Read note 22 §1–§5 before building a slice.

- **Code owns the mind; the model voices it.** Anything with stakes (the honesty move, whether to
  yield, grudges, forgetting) is decided by deterministic code. The model writes the words and,
  on the side call, labels what happened (closed enums only).
- **State.** Profile JSON on the library character (`lib_items.data.mind`, no migration). Seven
  new tables, one per slice, each row anchored on the message or extraction run that wrote it, so
  swipes and branches swap the mind for free: `mind_states` (affect, needs, counters),
  `opinions` (relationship ledger), `secrets`, `seeds` (worries, plans, news, corrections,
  positions), `goals`, `recollections`, `reflections`. Three memory columns (`valence`, `alts`,
  `core_locked`). Beliefs and who-knows-what stay in `knowledge`; labels stay in `edges`.
- **Per turn: 13 steps, 11 in code** (note 22 §2). The reply call gains a hidden two-line thought
  (standard level). At most one small closed-enum side call per turn on `utility`, after the reply
  by default, before it when a code gate fires (≤15% of turns). It replaces today's face call.
- **Between scenes: one job per tracked character per skip** (note 22 §3): a code tick, then one
  call that writes the diary, worth-telling news and 1–3 seeds; a deep pass on big skips.
- **Prompt: one mind block** in words, inside the volatile tail before `[Directive]` (~100 / 250 /
  400 tokens by level); decisions go inside `[Directive]`. The cached prefix does not change.
- **Mind levels** (renamed from note 22's tiers, because both products get every feature): the
  level changes *how* a feature is computed, never *whether* it exists.

| Level | Where it fits | Calls per turn | Features computed by |
|---|---|---|---|
| **lite** | CPU, 4–6 GB GPU, free credits | 1 (the reply) | code only; appraisal from rules and the built-in embedder |
| **standard** | 8 GB GPU (the default machine), online default | 2 (reply with inline thought + side call) | code + side call |
| **premium** | online strong models, 12 GB+ local | 2–3 (pre-reply mind call every turn) | code + pre-reply call + deep passes |

## 4. Two products, one engine

```
                 ┌──────────── desktop (GitHub releases, open source) ─────────────┐
 Electron UI ──► │ kataki serve  (one library, keys in the OS keychain, LocalHost)  │ ──► your models
                 └──────────────────────────────────────────────────────────────────┘
                 ┌──────────── Kataki online (hosted) ──────────────────────────────┐
 Web UI ──► gateway (auth, balance, billing) ──► kataki serve --hosted              │
                 │   one process, many libraries (one per user), OnlineHost:       │ ──► online providers
                 │   service keys, metering to the ledger, credit gate, channel    │     (service keys)
                 └──────────────────────────────────────────────────────────────────┘
```

- **Same engine, same routes, same features.** The engine takes a `Host` (track B, task B1): where
  keys come from, what to do with usage after each model call, whether a call is allowed (credit),
  which channel this user is on, and whether local-only routes exist.
- **Desktop-only by nature:** local server detection, backups on disk, GPU image generation, the
  keychain. Online replacements: the service's model catalogue, managed backups, cloud images.
- **Online-only by nature:** accounts, balance, top-ups, the price shown before a costly job. The
  gateway and billing ledger are their own spec (infrastructure Phase 6); this spec defines only
  the engine side of that contract (§8.4).
- **Pricing mechanics the engine owns:** a `usage_log` row for every model call (both products;
  desktop users with paid keys see "this story cost $0.12"), a price table (`prices` setting,
  pushed by the service online, optional on desktop), a per-turn estimate by mind level for the UI,
  and the credit gate (online) that refuses a call with error code `NO_CREDIT` before it is sent.
- **Default online models** (research note 21, price-based, quality to be checked by the probe
  sweep): reply GLM-5.3-Flash or DeepSeek V4.1 Flash with thinking off; utility Qwen3.7-Flash or
  gpt-oss-20b; background jobs on batch/off-peak variants. Estimated compute at standard level:
  about $0.58 / $3.49 / $11.63 a month for light / heavy / whale users before margin. Hosted voice
  is the budget-breaker; it is credits-only.

## 5. Alpha, beta, stable

- **One registry** (`engine/src/kataki/features.py`): each feature has a stage
  (`alpha | beta | stable`). A process or user has a channel (`alpha | beta | stable`). A feature is
  on when its stage is at or below the channel (alpha ⊃ beta ⊃ stable), unless the user turned it
  off (`features.<name>` setting = false) or, on alpha/beta, turned an earlier-stage one on.
- **Desktop channel** comes from the build (`KATAKI_CHANNEL`, set by Electron from the app version:
  `-alpha.N` → alpha, `-beta.N` → beta, else stable). **Online channel** comes from the account's
  beta flag, passed by the gateway into that user's `Host`.
- **Every slice ships alpha → beta → stable** on both products at once. Promotion to beta: its
  probes pass on the default local model and on the default online model, and no health metric
  regresses (§9). Promotion to stable: the owner's blind A/B win (≥60% of decided pairs) and one
  release on beta without a rollback.
- A feature that fails in the field is set back a stage in the registry (a one-line PR); its
  data stays and is simply not read.

## 6. Defaults, and the rules that keep roleplay possible

The defaults are "Natural": the realism group in Settings has four dials plus off-screen life,
and every character can override any of them (the existing knobs rule: the character's own
choice wins, "inherit" means the setting).

| Dial (setting key) | Values | Default |
|---|---|---|
| Pushback (`realism.pushback`) | soft · realistic · stubborn | realistic |
| Memory style (`realism.memory`) | faithful · human · dreamlike | human |
| Relationships (`realism.relationships`) | gentle · realistic · harsh | realistic |
| Texting (`realism.texting`) | off · light · natural · messy | light |
| Off-screen life (`realism.offscreen`) | off · on | on |
| Mind level (`mind.level`) | lite · standard · premium | standard desktop, standard online |
| Think first (`mind.thinkFirst`; a character's `data.mind.thinkFirst` wins) | when it matters · always · never | when it matters |

Rules no dial can break:

1. A character stays in the scene and keeps playing. Moods, grudges and refusals shape *how* they
   answer, never *whether* the story continues: no character ends a scene, leaves, or goes silent
   on their own for more than one reply.
2. The user's stop word (`realism.stopWord`, default `red`) ends any stance at once; hard lines on
   the card are enforced by code before generation.
3. A sincere out-of-character question (`((ooc: …))`, "are you an AI?") is answered out of the
   fiction, truthfully.
4. Pinned and `core_locked` memories are never distorted or forgotten; a character forgets only
   hazy memories, and "the app lost it" is never passed off as forgetting.
5. Every delay (typing, bursts, slow replies) can be skipped with one tap; long silences move on
   story time, not the user's real time.
6. Everything the mind decided is inspectable in Peek and Backstage, and the user can edit or
   reject it (a grudge, a ring, a recollection).

## 8. API contracts for the UI

The UI agent builds from these. Every new field is additive; old clients ignore it.

### 8.1 Foundation

- `GET /features` → `{"channel": "alpha", "features": {"mind.affect": {"stage": "alpha", "on": true}, …}}`
- `PUT /settings` accepts `features.<name>` (bool), `mind.level`, `realism.*` (§6).
- `GET /health` gains `"channel"` and `"host": "desktop" | "online"`. Online, `"channel"` is the
  account's (from the host), not the build's.

### 8.2 Slice 1

- `GET /stories/{id}/people` → each character gains
  `"mood": null | {"label": "hurt", "feels": "very hurt, and a little anxious", "shows": "calm",
  "tell": "short answers", "word": "low", "why": "Aren called her useless"}`.
  `feels` is private (Peek); `shows` and `tell` are what anyone could see.
- SSE `done` gains `"mood": {<speaker's mood, same shape>}`.
- `GET /messages/{id}/mind` gains an INSIDE node `{"id": "mood", "kind": "mood", "title": "Mood",
  "text": "very hurt · showing calm", "gold": true, "detail": <the mood object above>}` when the
  reply was written with a mood (kind `feeling` stays the relationship edges).
- A library that is newer than the engine: `kataki serve` prints a second JSON line
  `{"error": {"code": "LIBRARY_TOO_NEW", "message": "…"}}` and exits with code 3; the shell shows
  the message and offers to update. Before any migration a copy is kept as
  `backups/library-before-v<new>-from-v<old>.db` (it shows in Settings › Backups).
- `lib_items.data.mind` (PATCH `/library/{id}` with `data.mind`) is the profile editor's payload;
  shape in note 22 §1 (axes `[mean, spread]`, attachment, regulation, …).

**Slice 3** (plan `2026-09-29-minds-slice-3.md`):

- `GET /features` lists `mind.thought` (stage alpha). It gives a character's reply a private
  thought on the standard and premium levels; never the narrator's; not on lite.
- **When the header is asked** (`mind.thinkFirst`, §6): "when it matters" (default) asks for it
  only when the opener check is armed (cold, holding a position, a grudge, blunt), the latest
  user line carried an event, or the character has no thought yet in this scene; "always" every
  turn; "never" not at all (a reasoning model's afterthought is unaffected). A header on every
  turn cost ~2.5 s on the first word (latency probe), over the 2 s gate of the Mind graph spec
  §4.4/§7.1, so calm small talk skips it. `gen.trace.think` records why: `"armed"` | `"event"` |
  `"first"` | `"always"`, or null. Peek's `thought` looks back to the latest reply that had one.
- **The thought**, one shape everywhere below:
  `{"thinks": "Don't look at the ring.", "wants": "him to drop it" | null, "from": "before" | "after"}`.
  `thinks` is at most 25 words and `wants` at most 10, both in the character's own voice.
  `"before"`: written before the reply, which was written from it (show it as "Thought").
  `"after"`: written after the reply had begun, or, when the reply model is a reasoning model
  with its thinking on, read off the reply by the side call (show it as "Afterthought";
  `wants` is then null). Private: Peek and Backstage only. It is stored in
  `messages.gen.thought`, not in `messages.gen.mind` (that is the mood, §8.2).
- SSE: no new event. While the character writes the thought, `thought` events carry its raw
  text (`Mira thinks: …`), as they carry a reasoning model's thinking; the UI's "thinking"
  state is right for it. `done` gains `"thought": <the thought> | null`. A thought the model
  writes in the wrong place never stays in the saved reply; one written after the reply may
  already have streamed as tokens, so the UI keeps showing the saved text after its reload (as
  it does today).
  A header written as plain words (no tags) sends no `thought` events; the thought still arrives
  in `done.thought`.
- `GET /stories/{id}/people` → each character gains `"thought": <the thought, plus
  "message_id"> | null`: their latest thought on the active branch (older replies without one are looked past); null when
  they have none yet, or `mind.thought` is off.
- `GET /messages/{id}/mind` gains, when the reply has a thought, an INSIDE node
  `{"id": "thought", "kind": "thought", "title": "Thought" | "Afterthought", "text": <thinks>,
  "gold": <from is "before">, "detail": <the thought>}` and, when it has a want, a DECIDE node
  `{"id": "intent", "kind": "intent", "title": "Intent", "text": <wants>, "gold": <same>,
  "detail": <the thought>}`, linked thought → intent → spoke (gold when the thought came first).
  A thought with no want links to the Expression node, or to spoke, like the other gold INSIDE
  nodes. Goal nodes wait for slice 7's goals.
- Stored for Backstage, not yet in any route: `messages.gen.trace.echo`
  (`{"hit": "i promised myself i wouldn't", "resampled": true | false}`: the reply said five
  words of its thought in a row; in the opening it is dropped unseen and written again once,
  sharing the one retake per turn with the opener check), and `messages.gen.trace.ms.thought`
  (ms from the thought's first piece to the reply's first word). `gen.reasoning` and
  `gen.think_ms` now hold only a reasoning model's own thinking, never the character's thought.

**Slice 4** (plan `2026-09-30-minds-slice-4.md`):

- `GET /features` lists `mind.secrets` (stage alpha). Off: no secrets are read, decided, checked
  or shown, and out-of-character lines go to the story as before.
- **Where secrets come from:** the character card, `lib_items.data.mind.secrets` (PATCH
  `/library/{id}` with `data.mind`), copied into a story when it is created (stories made
  earlier have none; editing them in Backstage comes later):
  ```json
  {"text": "The ring in the drawer was her late brother's.", "keys": ["brother"],
   "topic": ["ring", "drawer"],
   "cover": "It was my grandmother's.", "conceal_from": "all" | [<library item ids>],
   "stakes": 0.8, "motive": "protect_self" | "protect_other" | "gain" | "avoid_conflict" | "kindness",
   "sincere": false}
  ```
  `keys` are the words that would give the truth away (the leak check looks for them; without
  keys a secret is never checked); `topic` the words that put it on the table (with the keys
  and the cover's words; the move is decided only then). `stakes` 0–1 (default 0.5), `cover` optional (no cover: she
  never lies about it, she evades or deflects), `sincere`: she believes the cover herself.
- `GET /stories/{id}/people` → each character gains `"secrets"`: `[]` when they have none or
  `mind.secrets` is off.
  ```json
  {"id": 3, "text": "The ring in the drawer was her late brother's.", "keys": ["brother"],
   "topic": ["ring", "drawer"],
   "cover": "It was my grandmother's." | null, "motive": "protect_self" | null, "stakes": 0.8,

  ```
  `status`: `exposed` once she confessed or told the truth to someone it was kept from (`told`),
  `suspected` once someone doubted her (she was accused, pressed, contradicted, or a hearer's
  belief in her claim fell; `suspected_by`), else `hidden`. `said` is the latest reply on the
  active branch in which she decided something about this secret (what she "said instead": show
  `label` and `text` with a spoiler toggle over `text`/`cover`). The truth is private: Peek and
  Backstage only.
- **The move** is one of `truth, soften, hedge, hint, omit, evade, deflect, exaggerate,
  white_lie, self_lie, confess, double_down` (`self_lie` = a self-serving lie; `exaggerate` is
  never chosen by code yet). Labels for the UI: truth "told the truth", soften "softened it",
  hedge "hedged", hint "let a hint slip", omit "kept it quiet", evade "refused to say",
  deflect "changed the subject", exaggerate "exaggerated", white_lie "told a white lie",
  self_lie "lied to cover it", confess "confessed", double_down "stuck to the story".
- Stored on the reply, `messages.gen.honest` (decided before the reply was written):
  `{"secret": 3 | null, "move": "self_lie", "why": "probe" | "topical" | "face", "caught": null |
  "accused" | "doubted" | "pressed", "to": 12, "inputs": {"stakes": 0.8, "closeness": 0.2,
  "honesty": 25, "candor": 50}, "told": []}`. `why: "face"` is an opinion asked on the user's
  own work (soften, hedge, white_lie, truth), with `secret: null`. `told`: the people it was
  kept from who heard her tell the truth or confess (from then on it is not kept from them).
- `gen.trace.leak = {"hit": "brother", "resampled": bool, "covered": bool}`: the reply said a
  key in front of someone it is kept from. `resampled`: it was in the first sentence, dropped
  unseen and written again once (the one retake per turn, shared with the opener and echo
  checks; never on lite, never on a turn where the secret was not on the table). `covered`: that
  sentence was replaced by the cover story (or dropped when there is none; with nothing said
  yet, a line like `*Mira looks away and changes the subject.*`) and the reply ended there.
  While the secret is on the table the reply is held back a sentence at a time; on other turns
  only the word being written is held, so a key never streams, but the first words of the
  leaking sentence may already be on screen: show `done.text` after `done` (the saved reply
  ends before that sentence).
- **Thinking on secret turns:** the raw `thought` events are the model's own words and may
  contain the secret's key; on a turn with `gen.trace.gate` (or always, to be safe) do not show
  them verbatim, show `done.thought` once `done` arrives.
- `gen.trace.gate`: the gate codes that fired (`["secret_topical", "probe"]`), or absent.
  `gen.trace.think` gains `"secret"` (a secret on the table is a reason to think first).
- `GET /messages/{id}/mind` gains, when `gen.honest` is set, a DECIDE node
  `{"id": "honest", "kind": "honest", "title": "Honest?", "text": "Lied to cover it:
  “It was my grandmother's.”", "gold": true, "detail": <gen.honest plus "label", "cover">}`,
  linked honest → spoke (gold).
- **Out of character** (§6 rule 3): a user line in `((ooc: …))`, `(ooc: …)` or starting `OOC:`,
  or a sincere "are you an AI / a chatbot / a language model?", is answered out of the fiction
  ("a bot", "a robot", "a real person", "a machine" count only inside an OOC marker: a story
  can ask its own people that). SSE:
  `meta` has `"ooc": true`, `"role": "ooc"`, `"speaker": null`; the answer streams as `token`s;
  `done` has `"ooc": true`. "Are you an AI" is answered by the app (no model call, always the
  truth); any other OOC question by the reply model as itself. Both lines are saved with
  `hidden: true` so no character, memory or prompt ever sees them; `GET /stories/{id}/messages`
  gains `"ooc": true` on them: show them as a system-styled aside, not folded into the hidden
  lines. A retake of an OOC answer answers again.

### 8.4 Engine ↔ gateway (track B)

- Gateway → engine (B4, `kataki serve --hosted`): on every request `X-Kataki-User` (library id,
  `[a-z0-9_-]{1,64}`, never `con`, `prn`, `aux`, `nul`, `com1`–`9`, `lpt1`–`9`), `X-Kataki-Channel`, `X-Kataki-Time` (unix seconds, digits only) and `X-Kataki-Sig`,
  the hex HMAC-SHA256 of `user\nchannel\ntime\nmethod\ntarget` (`target` is the path and query
  as sent, `?` always there: `/stories/1/turn?`) with the shared secret (at least 32 bytes; `KATAKI_GATEWAY_SECRET`,
  else the keychain's `kataki-gateway`/`secret`). Missing, tampered, a bad user id, or a time more
  than 60 s off: 401 `{"detail": "missing or invalid gateway signature"}` and no library is opened.
  The engine opens `<root>/<user>/library.db` on demand (LRU, closed after idle time) and writes
  the service's catalogue (its `providers`, `model_roles` and `prices`, from `--catalogue`, a
  library file) into it at every open. The desktop never reads these headers. The process binds
  127.0.0.1 unless `--bind` says otherwise.
- Engine → gateway, under one base URL (`--gateway`), with `Authorization: Bearer
  {KATAKI_GATEWAY_KEY}` (else the keychain's `kataki-gateway`/`key`): for every model call,
  `POST {gateway}/usage` with the meter row below plus `"user"`; idempotent on `usage_id`, tried
  twice (2 s timeout each). A row it could not take stays `metered=0` and is sent again (oldest
  first, each with its `usage_log.at`, UTC, so it is billed to the day it was used) when its
  library opens and at every idle sweep: the outbox. A row the gateway refuses
  as malformed (400, 422) is set aside as `metered=2` (logged by `usage_id`) and the rest still
  go; 409 means the gateway already has that `usage_id` (counted as sent); any other failure stops that library's outbox, and the sweep sends no
  other library's until the next pass. Before every call, `GET {gateway}/allow?user=&estimate=` (dollars) → `{"ok": bool}`,
  cached per user for 10 s (both answers); an error or a non-2xx refuses.
- **The ledger computes in integer micro-dollars** from the row's tokens and the price table
  (`usage.micros`: $ per million tokens is micro-dollars per token; exact decimal, rounded half-up
  once per call), never from `cost`, which is a float for display.
- **Daily cap** (B5): before the gateway is asked, a call that would take the user's spend today
  (UTC, in micro-dollars from each `usage_log` row's tokens, as the ledger bills) past the cap (`--daily-cap`, default $5) is refused with
  `DailyCap`, code `DAILY_CAP`, on every surface NO_CREDIT has (SSE `error` code, 402 `code`,
  the worker stops). A user's model calls in flight are capped (`--max-calls`, default 4): past
  it a call waits, it is not refused.
- **The `Host`** (`engine/src/kataki/host.py`, B1) is how the engine asks all of this:
  `get_key(provider) -> key`, `meter(row)` (online: the POST above), `allow(ep, estimate_usd)
  -> bool`, `channel() -> "alpha" | "beta" | "stable"`, `prices() -> table`, `local_routes`.
  `LocalHost` is the desktop (keychain/env keys, no meter, no gate, `KATAKI_CHANNEL`, the library's
  `prices` setting, local routes on). `OnlineHost` takes each answer from the service; its `allow`
  fails closed (a callback that raises refuses). The gateway client (B4) owns the HTTP, the 10 s
  `allow` cache and retrying the POST; the engine calls the host synchronously. One `LLM` per
  app: `create_app` with a metering or gating host refuses an `LLM` that already has `on_usage` or
  `allow` set (a shared one would bill one user's calls to another).
- **Meter row** (what `meter` gets, one per model call, after it is in `usage_log`):
  `{"usage_id": uuid hex, "story_id", "role", "model", "prompt_tokens", "cached_tokens",
  "completion_tokens", "cost": $ | null, "estimated": bool}`. `usage_id` is stored on the row
  (v18), so the ledger and `usage_log` can be matched (B6); `usage_log.metered` (v18) turns 1 once
  `meter` returned, so a row the meter could not take stays 0 for B4's outbox to send again. `estimated` is true when the provider
  never reported usage (a stopped or dropped stream, a stream that failed mid-way, a backend that
  sends none): prompt characters / 4 in, streamed characters / 4 out. Role `voice` rows hold
  characters in `prompt_tokens`.
- **The gate:** before every request of every model call (replies, side calls, extraction, diary
  calls, embeddings, speech), `allow(ep, estimate)`; `estimate` is prompt characters / 4 in and the
  request's `max_tokens` (else 1000) out, priced by the host's table. A model the table does not
  price is refused online without asking (the host never gets a `null` estimate). Online, a role's
  `params.body` reaches the request only for sampler keys (`llm.SAMPLER_KEYS`: temperature, top-p/k,
  min-p, penalties, stop, seed, DRY, XTC, …), never `model`, `n`, `stream_options` or `max_tokens`;
  the desktop sends it verbatim. A refusal raises `NoCredit` (code `NO_CREDIT`) and nothing is sent. Surfaces: a turn sends SSE
  `error` `{"message", "code": "NO_CREDIT", "message_id"?}` and saves no reply (a retake whose
  second take is refused keeps the first, already paid take, saved with `finish` `error`, and its
  `message_id` is in the event); a JSON route
  answers **402** `{"code": "NO_CREDIT", "detail": {"code": "NO_CREDIT", "message"}}`; a side call
  or face call after a reply is skipped (the reply stays); a refused memory read leaves its lines
  unread (no failed run, no attempt counted); a refused diary call stays `pending`; the background
  worker stops at the first refusal. The desktop never refuses.
- **Prices** (`prices`, B2): `{"<model>": {"input": $/M, "cached": $/M, "output": $/M}}`, and for a
  speech model `{"char": $/M characters}`; `cached` defaults to `input`, and an embed model's
  `output` to 0. On the desktop it is an
  optional setting (`PUT /settings {"prices": …}`); online it is the service's table from the host,
  and `PUT /settings` refuses `prices` with 403. Each `usage_log` row stores its cost when recorded.
- **Local-only routes answer 404 online:** `/providers*` (CRUD, model lists, detection),
  `/storage`, `/backups*`, and the paid picture routes `/library/{id}/draw` and `/library/{id}/look`
  (the image client has no gate or meter yet; they stay 404 online until it has, B4). `POST /import/kataki` online leaves `providers`,
  `model_roles`, `settings` and `usage_log` as they are (`archive.MANAGED`).

UI (B2):

- `GET /stories/{id}/spend` → `{"calls": 12, "cost": 0.0123, "unpriced": 0, "estimated": 1,
  "by_role": {"rp": {"calls", "cost", "prompt_tokens", "cached_tokens", "completion_tokens"}, …},
  "by_day": [{"day": "2026-09-30", "calls", "cost"}, …], "per_turn": {"level": "standard",
  "lite": 0.0004 | null, "standard": …, "premium": …}}`. `cost` sums priced calls (a row recorded
  before any price was set is priced at today's table); `unpriced` counts calls with no price
  (local models); `per_turn` is `null` for a level when a model it uses has no price. `GET` only:
  no call is made.
